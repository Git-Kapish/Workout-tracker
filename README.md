# Tally

A personal workout tracker for one person on one iPhone. Log exercises (sets, reps, weight), see each week against the last, and track every exercise over time. Everything is stored on the phone: no account, no server, no network.

Built with Expo (React Native) and TypeScript. SQLite holds the data.

## What it does

- **Today**: log an exercise in a few taps (names autocomplete and prefill from your last session), see today's log and this week vs last week.
- **Week**: browse any Monday to Sunday week, day by day, with totals.
- **Progress**: this week vs last week for exercises, sets, reps and volume, plus an 8-week chart.
- **Exercises**: search every exercise, see personal bests and a weight-over-time chart.
- **Export**: the download button on Today shares all your data as a CSV (Save to Files, AirDrop, Mail).

Weights are in kg. Weeks start on Monday.

## Run it on your iPhone (free, Expo Go)

You need Node.js (LTS), Git, and the **Expo Go** app from the App Store. Expo Go must support the SDK this project uses (**Expo SDK 58**); update Expo Go if it refuses to open the project.

```powershell
npm install
npx expo start
```

Scan the QR code with the iPhone camera and it opens in Expo Go. The laptop and the phone must be on the same Wi-Fi. If the phone cannot reach the laptop (guest or work Wi-Fi), use:

```powershell
npx expo start --tunnel
```

Two things to know about this setup:

- **The laptop must be running `npx expo start` whenever you open the app.** Expo Go loads the app from your laptop; it is not installed as a stand-alone app. To get a permanent app, see "Make it permanent" below.
- **Your data lives inside Expo Go on the phone.** Deleting Expo Go, or removing the project from it, deletes the workouts. Updating the app or restarting the phone does not.

## Back up your data

Tap the **download button** at the top right of Today (or **Settings > Export all data**) and save the CSV somewhere safe (Files, iCloud Drive, AirDrop to the laptop). Do this weekly.

The file is `tally-export-YYYY-MM-DD.csv` with the columns `date,exercise,sets,reps,weight_kg`, opens in Numbers or Excel, and includes every entry.

> **Important:** the app can export but **cannot import yet**. The CSV protects you in the sense that your history is safe and readable, but restoring it into the app would need CSV import, which is not built (it was marked optional in the plan).

## Settings and the app icon

The **sliders button** next to the download button on Today opens Settings. **App icon** offers Dark (the default), Light and Brand, all from the logo pack in `tally-logo-pack/`.

> **Expo Go cannot change its own icon**, and it never shows Tally's icon anyway. In Expo Go your choice is only remembered. The Home Screen icon really changes only in an installed build (TestFlight, see below), because the alternate icons are compiled into the app. `expo-alternate-app-icons` has not been run on SDK 58 on a real device yet.

## Run the checks

```powershell
npm run check        # lint + type-check + all tests (run this before any change is "done")
npm run lint         # ESLint, including the architecture boundary rules
npm run typecheck    # tsc --noEmit
npm run test         # Jest
npm run format       # Prettier
```

Tests run on your laptop, including the database tests, which use a real SQLite engine (`better-sqlite3`, a dev-only dependency). They cover the date and week rules, totals and percent changes, validation, CSV, the repository and migrations, and the screens.

Typed routes (`.expo/types`) are generated by the dev server, so after adding a screen run `npx expo start` once before `npm run typecheck`.

## Developer tools

In a development build such as Expo Go, **long-press the greeting on Today** to open a hidden screen that adds 5,000 clearly named fake entries (to check performance on the phone) and removes them again. It never touches your own entries, and it does nothing in a release build.

## How the code is organised

```
app/            screens (Expo Router): Today, Week, Progress, Exercises, exercise detail, log sheet, welcome
src/lib/        pure logic: dates, weeks, metrics, comparison, validation, formatting, CSV (no React, no I/O)
src/db/         the only place with SQL: repository, migrations, expo-sqlite client
src/hooks/      data hooks used by screens
src/components/ UI building blocks
src/platform/   thin wrappers over native modules (file export and sharing)
src/theme/      colours (light and dark), spacing, type
__tests__/      tests that mirror the above
docs/           design screenshots and the Phase 6 checklist
```

Layer rules (for example "screens never touch SQL") are enforced by ESLint, so `npm run check` fails if one is broken.

## Make it permanent (optional, $99 per year)

Expo Go needs the laptop. To get Tally as a normal app on the phone you need an **Apple Developer account** in your own name and a TestFlight build. This is not set up yet; the outline is:

1. Join the Apple Developer Program (developer.apple.com).
2. Install and sign in to the build tool: `npm install -g eas-cli`, then `eas login` (an Expo account).
3. Add a bundle identifier to `app.json` (`expo.ios.bundleIdentifier`, for example `com.yourname.tally`) and run `eas build:configure`.
4. Build: `eas build --platform ios --profile production`. No Mac is needed.
5. Send it to TestFlight: `eas submit --platform ios`, then install it from the TestFlight app.

You enter your Apple ID and password yourself when the tools ask. Never paste them into a chat, a file or a commit. Your data does not carry over from Expo Go to the new app, so export a CSV first, and note that import does not exist yet.

## Not included (by design)

Cloud sync, accounts, CSV import, rest timer, workout templates, lb/kg switching, Apple Health. See `plan.md` section 12.
